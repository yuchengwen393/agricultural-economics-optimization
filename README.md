# 空天地信息支持下辽宁丘陵玉米植保协同调度优化研究

> 基于合同任务包的多目标混合整数规划与风险决策 · 农业经济建模优化项目

本仓库是对「空天地信息支持下辽宁丘陵玉米植保协同调度优化研究」项目的完整整理，包含**代码、数据集、求解结果、建模方法**与**说明文档**，可按分类复现从原始数据审计到求解验证的全流程。

---

## 一、项目简介

针对辽宁丘陵地区玉米集中植保中**作业窗口受限、车辆与无人机补给耦合、外援参与条件**影响统一调度的问题，建立以公共服务协调者为决策主体的**合同任务包优化模型**。研究整合历史玉米分布、公开道路、数字表面模型与再分析天气，构建建平县 50 个研究服务单元，将天气适作、车机同步、电池充电、药液补给和外援必要收益条件纳入连续时间资源模拟，并通过贪心启发式、自适应大邻域搜索（ALNS）与混合整数规划（MILP）选择班组完整任务包，进一步开展预算鲁棒保护与样本均值近似下的尾部风险评价。

**关键结论（基准设计情景）：**

| 指标 | 数值 |
|---|---|
| 研究服务单元 | 50 个，总支持面积 2175.29 亩 |
| 完整及时服务 | 1634.60 亩（及时率 **75.14%**） |
| 作业服务支出 | 8182.94 元 |
| 最差接入组及时率 | 72.41% |
| 候选路线池 | 1040 条（主目标 gap = 0 仅对该受限池成立） |

> **边界说明**：这是 2026 研究设计（历史 2020 玉米空间支持 + 2026 道路/报价参考 + 历史天气压力测试），**不是真实订单回测**。无入口/药剂/障碍真值时，不认证航线可执行、不启用地面喷雾机、不货币化农业损失；未取得的必要微观数据如实保留缺失，不伪造实测值。

## 三、研究方法与技术路线

整个研究按六个阶段推进，各阶段产物在仓库中可对应到相应目录：

1. **数据审计**（`data/01_数据审计`、`code/audit_inputs.py`）
   核查原始资料包（5457 个文件、约 16.4 GB），建立数据缺口与来源台账，区分**公开证据、透明派生量、待核验研究假设**三级参数。

2. **数据检索与采集**（`code/fetch_sources.py`）
   检索原始文献、官方规格及公共数据，保存获取与失败记录；默认离线使用已下载数据，公开补充下载为可选开关。

3. **可复算实例构建**（`code/prepare_data.py`、`data/02_处理数据`）
   用真实区域（建平县）和气象数据建立 50 个研究服务单元：将 2020 年玉米像元聚合为 300 m 格网，按面积 15–110 亩、距锚点 ≤6 km、接入距离 ≤1200 m 筛选后径向选取。

4. **模型构建**（`code/optimization.py`、`modeling/03_模型与方法`）
   建立**合同任务包 / 班组路线集合划分 MILP**：以未服务及逾期服务的风险面积代理最小为主目标、作业服务支出最小为次目标；融合资源调度、动态规划、ALNS、鲁棒缓冲及情景检验。

5. **求解与核验**（`code/supplementary.py`、`code/validate_outputs.py`、`results/04_求解结果`、`results/07_验收核对`）
   进行对照、多目标、预算/服务公平/天气灵敏度与独立可行性核验；主矩阵独立重建、小实例穷举与事件/成本核验一致。

6. **输出**（`results`、`docs`、`code/paper_build`）
   输出模型公式、结果、代码、图表、数据字典与文件用途清单。

## 四、核心模型要点

- **决策主体**：具有采购预算的公共植保服务协调者，拥有 3 支自有班组，可向 2 支外援班组购买整日任务包。
- **主问题**：从资源模拟已通过的候选任务包中，用集合划分模型选择覆盖、预算与班组互斥约束下的方案。
- **主目标**：风险面积代理最小（未服务 + 逾期）；**次目标**：作业服务支出最小（主目标不变时压缩）。
- **风险处理**：Bertsimas–Sim 预算不确定集合约束转场偏差；条件风险价值（CVaR）评价天气尾部风险。
- **核验**：独立事件检查、稀疏矩阵复核、小实例穷举。

## 五、复现方法

1. 安装依赖：`pip install -r code/requirements.lock.txt`
2. 运行一键入口（PowerShell）：`code/run_pipeline.ps1`
   - 默认离线使用已下载数据；公开补充下载为可选开关 `FetchPublic`（可能需要网络授权）。
   - 源码内已固定随机种子，`code/config.json` 保留全部经营假设。
3. 重跑会更新生成产物；首次复制到其他机器需调整脚本内根路径并安装依赖，不能声称完全免配置移植。

## 六、数据与边界声明

- 道路网络来自 OpenStreetMap（`data/liaoning_input_copy.pbf`），路面属性缺失 63.71%、宽度全部缺失，因此仅提供主要转场结构，具体入口仍需核验。
- 天气来自再分析产品（ERA5-Land / ERA5），10 m 再分析风不能替代现场冠层风。
- 多种资料时间不完全一致，据此构建 2026 研究设计情景，而非复原某一历史年度已发生的服务经营。
- 缺少 50 个单元对应的确权边界、当期植保订单、病虫诊断、实测入口、车辆轨迹与具体外援报价，这些缺口如实保留。
